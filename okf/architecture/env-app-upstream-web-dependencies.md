# Summary

Env App is built as a Redeven-specific shell on top of published floe-webapp UI/runtime primitives, floe-webapp protocol connectivity, Floeterm terminal-web components, and Flowersec controlplane artifact helpers.

Env App composes published floe-webapp, Floeterm, and Flowersec web packages.

# Contract

## Mechanism

The browser dependency set includes the public Floeterm terminal-web v0.16.4 release, Floe Webapp Boot, Core, and Protocol v0.41.4, and Flowersec Core v2.5.2. Terminal-web is semantic-only and has no Ghostty WebAssembly or Beamterm dependency. Every published UI dependency resolves from the public npm registry. Local paths, links, workspaces, portals, aliases, runtime patches, private registries, and renderer fallbacks remain forbidden.

The UI package pins Floe Webapp Boot, Core, and Protocol v0.41.4 and Flowersec Core v2.5.2 from the public registry. Each Floe package carries its own MIT metadata and license file. Floe Webapp owns shell presets, generated token CSS, Monaco themes, accessible menu navigation, floating layers, bottom-bar companion behavior, terminal classification of rejected trusted spend bindings, and protocol-controller lifecycle ownership. The controller fences state writes by owner generation, and Env App secure-session retry calls the published `replaceConnection()` operation so an old asynchronous close cannot overwrite the newly installed connection with `idle`. Redeven selects those public contracts and derives product semantic aliases from the active preset; it does not fork the catalog, synthesize a second token map, recreate upstream keyboard and layer state machines, or add a second retry policy for rejected bindings. Shiki syntax themes remain a scoped exception while their chrome follows the shell preset, and Mermaid receives browser-resolved canonical sRGB colors with preset identity in its render cache key.

Terminal surfaces import Floeterm's semantic, live, and sessions entry points. `TerminalSessionRuntime` is a thin adapter around one `RendererSurface`, one `TerminalInputBridge`, one live attachment, and generation-bound semantic history and clear controls. Activity and Workbench reuse that runtime and the same controller/observer contract. The catalog stays renderer-free, dormant sessions stay metadata-only, and the initial build graph rejects terminal live or renderer modules. The complete terminal interaction contract is [Workbench terminal interaction](../ui/workbench-terminal-interaction.md).

Floeterm terminal-web v0.16.4 publishes the semantic Presentation validator, complete history viewport controller, isolated occurrence-level history search controller, compact continuation transport, `RendererSurface`, `TerminalInputBridge`, live codec, session metadata helpers, shell-integration display normalizers, theme catalog, and input intent types. A history viewport is one atomic server snapshot with canonical width and height even when its compact payload crosses multiple transport chunks. The Presentation preserves explicit ANSI indexed/RGB colors, inverse-cell state, cell attributes, grapheme width, hyperlinks, cursor state, graphics, geometry, and semantic history metadata. View-local default foreground, background, cursor fallback, search decoration, selection, typography, and DPR are applied only while painting; palette changes repaint the latest Presentation without changing PTY state or sequence. Clipboard copy stays on the browser's synchronous copy event, while paste uses the bounded semantic paste channel instead of ordinary text input. Repeated browser clicks remain view-local renderer gestures: double click selects one semantic word and triple click selects the logical row without splitting wide cells. Redeven adds product placement, permission mapping, local-path capability, file preview, safe external-URL activation, and Activity/Workbench chrome, but it does not parse PTY output or infer terminal state.

Runtime reconnect configuration uses Flowersec's discriminated `ArtifactSource` contract directly. Both Local UI and remote controlplane paths use Floe Webapp's `createControlplaneArtifactSource` because each attempt must mint and durably spend a fresh credential; no fixed artifact is reused or given an auto-reconnect escape path. The Local UI adapter feeds its already issued same-origin acquisition through the published source with `window.location.origin`, the same-origin spend endpoint, and exact validation that launcher, runtime, and app origins all equal the current page and that the tagged environment target matches `env_local`. Remote entry-ticket exchange uses the same public source and `acquire`, forwards abort and trace context, commits spend through the control-plane endpoint, and validates the exact current environment and Floe App binding. Artifact requests retain the upstream HTTPS default and redirect rejection; Env App enables loopback HTTP only when the current page is itself an HTTP canonical loopback location, while network HTTP remains denied.

Env App constructs one stable reconnect config for each transport mode so hard reconnects preserve Flowersec trace and source-consumption state. Before remote acquisition it establishes exact `/_redeven_sw.js` Service Worker control at scope `/`; failure stops bootstrap. One released Floe `ProxyBootstrapOwner` owns the runtime generation, and its Redeven adapter refuses any other script, scope, or uncontrolled page. Local Direct explicitly allows plaintext only for canonical loopback authorities and enables 15-second Yamux liveness with a 10-second timeout. Remote Tunnel explicitly requires TLS and retains Flowersec's tunnel liveness default. Both paths select 64 KiB outbound records and explicit WebSocket and Yamux queue, frame, stream, and receive-memory limits.

After an already opened Env App loses connectivity, Redeven projects published Flowersec `onDiagnosticEvent` reconnect events into one immutable product recovery snapshot. The `reconnect` stage, event code, result, and monotonic `attempt_seq` are the source for fast-reconnect attempts; Redeven does not recreate Flowersec's retry loop. Runtime availability probes return structured availability, access state, failure code, and HTTP status, and error classification uses only those fields and error types rather than message fragments. A Desktop-hosted session also subscribes to its sender-scoped transport-recovery snapshot. While that bridge is `waiting`, `connecting`, or terminally `failed`, Env App pauses its own Runtime probe loop; a recovered bridge advances directly to protocol reconnect. Generation and revision checks discard stale Desktop updates, and no layer replays the request that observed the disconnect.

Terminal diagnostics are view-local and content-free. They project attachment lifecycle, Presentation and geometry sequence, semantic history revision, resize settlement, and structured Floeterm error codes. Debug Console never retains terminal input, output, session id, connection id, path, raw server message, or raw failure cause. Sequence, geometry, and lifecycle generations remain distinct, and stale events cannot commit into a newer connection.

The catalog adapter is a separate static module from Floeterm live transport and rendering. Initial catalog hydration cannot pull the semantic renderer or live codec into the Env bootstrap. Semantic history is queried lazily by a mounted view. Each view owns its scroll target, serialized request lane, complete-frame cache, selection, and projection; search uses Floeterm's separate server frontier and never replaces the browse frontier. Connection-generation change, content epoch change, geometry change, clear, delete, permission loss, and disposal invalidate those resources, while ordinary live output advances in the background without replacing a visible immutable history viewport. There is no browser checkpoint, prepared raw history, replay queue, or warm-core VT cache.

Each `TerminalSessionRuntimeStatus` belongs to one mounted view. Activity and Workbench may fail or reconnect independently while still consuming the same actor-owned Presentation. A selected view explicitly activates the grid measured from its untransformed host layout content box before focus or input; an activation rejection remains the precise fail-closed error and admits no PTY write. The outer display mode and Workbench selection gate that interaction, so a hidden kept-alive peer cannot retake controller ownership. The runtime root reports `aria-busy=true` only until the first valid Presentation is painted; later view-local history projection remains interactive. Permission, protocol, actor, and semantic validation errors stay explicit instead of being reclassified from message text.

Env App keeps only bootstrap, access, protocol, and shell chrome in the initial module. Activity surfaces, Workbench, Terminal, Monitor, Files, Codespaces, Ports, Flower, Codex, Settings, Plugins, Debug Console, audit, file browser, and file preview hosts are loaded through feature boundaries when activated. Flower and Codex providers are scoped to the surfaces that need them, so a connected shell does not initialize AI settings, model catalogs, or thread lists by default. Feature CSS follows the same boundary: Iosevka loads with Terminal, shared Flower and chat styles load with Flower entry points, Codex styles load with Codex entry points, and the upstream KaTeX stylesheet and fonts load with Markdown preview. Markdown math retains KaTeX's `htmlAndMathml` output so the official feature stylesheet presents one visual formula while preserving the assistive MathML representation.

Activity navigation does not replace the Activity Shell or change its outer provider structure. `ActivityAppsMain` is the lifetime owner for Activity surfaces: a surface mounts on first activation and remains mounted but hidden while another Activity surface is active. This preserves file browser path, expanded directories, filtering, view mode, selection, scroll position, and equivalent local state in Terminal, Monitor, Flower, Codex, and other registered Activity surfaces. Activity and Workbench are themselves two lazily visited views in one `KeepAliveStack`; after first activation, switching display mode changes visibility and activation after paint without destroying either view. Activity navigation, display-mode navigation, and Workbench widget activation therefore share the same lifetime rule: lazy before first visit, stable DOM/provider/data-flow identity after first visit.

Connection recovery preserves those lifetime owners. Activity and Workbench each mount the same `ConnectionRecoveryView` once at their content root while their existing page DOM remains mounted. The underlying content container becomes `inert`, pointer-disabled, and `aria-hidden`; Terminal, Files, Monitor, Workbench widgets, and other surfaces do not own separate connection curtains or continue accepting stale input. The recovery presentation derives a fixed applicable-step timeline, exact completed-step percentage, real attempt counts, and only known retry timestamps from the immutable snapshot. Successful recovery remains visible for 1.5 seconds before the snapshot returns to idle and the original surface becomes interactive again. Terminal failure retains the window, focuses an alert heading, keeps technical details collapsed by default, and exposes only actions present in the Desktop snapshot. Raw HTTP status text is diagnostic detail rather than primary recovery copy.

The released floe-webapp selection controller separates immediate visual selection from committed content. Env App opts the Shell into UI-first Activity selection, uses after-paint activation for `ActivityAppsMain`, and uses another UI-first controller plus after-paint `KeepAliveStack` activation for Activity/Workbench mode changes. User input uses the delayed transaction path; initialization, restore, permission fallback, and other canonical corrections may commit synchronously. Persistence runs from the committed state rather than from a visual preview. Navigation does not suspend hidden surfaces, stop subscriptions, hibernate terminal cores, refetch warm content, or recreate providers; only visibility-dependent focus, resize, scroll restoration, viewport movement, and measurement may run after the target content has painted.

Codex keeps its heavy provider and feature CSS behind the lazy `CodexActivitySurface` boundary. The surface creates one shared Codex provider for the page and sidebar. The page stays inside the kept-alive Activity view, while the sidebar is projected through a Solid Portal into a lightweight Shell-owned host that exists only while Codex is active and permitted. The Portal mount remains stable when that host is removed or recreated, so returning to Codex moves the existing sidebar tree instead of recreating the provider, page, thread state, drafts, or sidebar-local state. If the Codex chunk resolves after navigation has already left Codex, it may finish mounting inside the hidden kept-alive surface without replacing the Shell or another Activity page.

The local bootstrap reuses the access status returned by `getLocalRuntime()` instead of issuing a second access-status request. Production builds enforce compressed initial-resource budgets of 600 KiB JavaScript, 120 KiB critical CSS, and 720 KiB total. The budget check also rejects initial HTML references to Markdown, KaTeX, Mermaid, Monaco, Excel, PDF, Shiki, Flower, or Codex feature assets.

Terminal stream lifetime and native autofocus are separate contracts. A kept-alive hidden surface may retain its attachment only while product policy keeps that view active; an observer never writes input or geometry. Its canvas stays hidden while the host has no usable bounds and becomes visible only after one atomic render has matched the current host content box and DPR, so an old small bitmap is never stretched during tab activation. The Floe mobile keyboard may leave the semantic textarea unfocused. Every asynchronous attach, activate, resize, history, search, clear, and repaint path checks the view disposal and connection-generation fences, so an unmounted surface cannot reopen a stream or apply a stale result.

Floeterm semantic logger callbacks are strict content-free product adapters. Redeven emits stable event and error codes with numeric or boolean metadata, never raw `Error` objects, upstream messages, terminal content, or encoded content. Console privacy tests reject both a unique raw secret and its encoded form.

Renderer validation keeps distinct evidence boundaries. The built-dist shell smoke serves only production Env App assets and proves a nonblank root, expected title, content-hashed JavaScript and CSS, and no framework or browser errors; it does not claim terminal coverage. The semantic terminal carrier separately starts a temporary production Redeven Runtime and drives the real Local UI, Direct transport, terminal-go SessionActor, PTY, Activity, Workbench, `RendererSurface`, and `TerminalInputBridge` path in headless Chromium. It verifies one semantic canvas, canonical frame geometry, DPR backing, nontransparent paint, actor-owned clear, history projection, controller transfer, refresh, and twenty `top` resizes. Automated gates do not start Desktop and do not claim packaged Electron evidence.

The carrier uses reused and fresh browser contexts, opens Activity and Workbench on the same session, and proves their Presentation sequence, content epoch, and frame geometry converge. Refresh preserves the existing canvas and receives a new Presentation even at unchanged geometry. Input probes use the real PTY, and any page, console, request, response, or semantic error fails the sample.

# Boundaries

This concept only holds while Env App consumes published upstream packages. Redeven may select shell presets and map product permissions, credentials, local-path authority, and placement into upstream contracts, but it must not recreate Floe shell tokens, Flowersec reconnect/framing/RPC behavior, or Floeterm parsing, key encoding, history, attachment arbitration, geometry, Presentation encoding, cursor, graphics, or canvas rendering. Browser Ghostty, TerminalCore, checkpoint workers, raw replay, Beamterm, hidden compatibility canvases, and local sibling dependency wiring are prohibited. Lazy boundaries change loading time, not product contracts or state ownership.

The Env App recovery snapshot is a product presentation projection, not another protocol or Desktop transport mechanism. It must not infer retry timing, parse failure prose, invent attempts, add a backup URL, retry through public Local UI, migrate streams, rebind a stale session, or replay user requests. Explicit Start, Restart, Stop, and Update continue to hand off to Desktop Welcome and remain outside this post-open recovery flow.
