# Summary

Redeven runtime builds control and data sessions on Flowersec v2 artifact, lease, connection-controller, session, RPC, and byte-stream primitives, while terminal lifecycle inside the runtime is delegated to Floeterm's terminal-go manager. Floeterm preserves valid user Bash prompt commands as independent syntax units; invalid user scripts remain Bash errors and are not normalized or hidden.

Runtime transport uses Flowersec sessions while terminal lifecycle is delegated to Floeterm managers.

# Contract

## AI Flower RPC registration

The local direct and remote agent production session profiles register the
complete AI request inventory before Flowersec freezes a session. The shared
inventory covers send, summary/thread subscription, message listing, Stop,
input response, and context compaction; the event type is explicitly a server
notification rather than a request handler. A declared AI method therefore
cannot fail at the router with a missing-handler 404. If the AI service or a
local realtime peer is not ready, the registered handler returns a structured
503 and the session remains usable. Env Local live timeline ownership is
HTTP/SSE, so its turn admission does not issue a second best-effort thread
subscription RPC. Stop remains a single AI RPC lifecycle command and does not
fall back to another transport.

## Mechanism

The released runtime dependency set includes Floeterm terminal-go v0.8.7 and Flowersec Go v2.3.9.

Redeven pins released `flowersec-go` and `terminal-go` versions in `go.mod`. The runtime consumes Flowersec Go v2.3.9 and the browser surfaces consume Flowersec Core v2.3.9 through published packages only. The agent owns connection and retry lifecycle through Flowersec's `ConnectionController` and `Connect` APIs, while Env App tunnel reconnects select the matching TypeScript policy. Local UI direct reconnects first resolve the hostname with `resolveLocalTransportSecurityPolicy` and permit plaintext only for canonical loopback authorities; non-loopback direct admission fails closed. When the public page uses plaintext `localhost`, Redeven maps its already validated listener identity to the actual same-port loopback IP authority before issuing the direct artifact, and uses that one authority for both the Flowersec candidate and upstream address. This is a product adapter to Flowersec v2.3.9's published IP-literal plaintext contract, not an alternate URL validator or a relaxation of that contract. The Docker Local UI integration client applies the same selection so its two-container network test proves the host-scoped admission boundary rather than unrestricted plaintext. Product code therefore does not depend on a permissive library default and cannot silently accept unrelated remote `ws://` transport.

Flowersec proxy requests use the validated browser source and origin context; payload-provided external origins are ignored, and opaque origins do not become forwarded request metadata. The Go HTTP proxy returns the first 3xx response with its original `Location` instead of following redirects. Browser Service Worker streams use one outstanding `chunk_credit_v1` credit per pull when both sides advertise the capability, while legacy workers retain their previous behavior; cancellation wakes waiting consumers. The optional Yamux stream write queue budget defaults to 4 MiB and is released after each write so an exhausted stream can recover. Reconnect paths share the active promise for the same configuration, including during backoff, preventing duplicate connection attempts without adding a global scheduler.

Code App and Port Forward sessions expose only Flowersec proxy handlers to product callers, but their server still registers an empty Flowersec RPC router because the released high-level connector creates and retains an `rpc` bootstrap stream for the connection lifetime. Unknown RPC types return the standard 404 response and do not close that bootstrap stream. These sessions do not register Redeven business RPC handlers, and they use the same private server constructor so the required transport lifecycle cannot drift between the two proxy products.

The control Direct session replaces record-level keepalive writes with acknowledged Yamux liveness probes at a 15-second interval and a 10-second timeout. Tunnel sessions keep Flowersec's idle-timeout-derived liveness policy. Runtime client, endpoint, and Local UI Direct server setup all select 64 KiB outbound encrypted-record chunks and explicit Yamux limits: 64 active streams, 32 inbound streams, 256 KiB frames and per-stream receive memory, 64 KiB preferred outbound frames, and 16 MiB session receive memory. Runtime RPC streams start request handlers only when work is available, run at most 32 handlers concurrently, and hold at most 128 pending requests in FIFO order; notification queues remain bounded at 128 entries. Desktop SSH streaming commands distinguish caller-requested termination from an unexpected remote exit: explicit termination waits for the command's complete close lifecycle and does not start a post-termination control health probe, while unexpected failures still verify the reusable control transport before classification. Redeven's runtime proxy product adapter blocks only CSP, CSP Report Only, and X-Frame-Options because those embedding policies conflict with proxied product surfaces; Flowersec continues forwarding the remaining default security headers. These are transport and product-policy controls; Redeven does not copy Flowersec framing, multiplexing, RPC scheduling, proxy filtering, or protocol implementation.

The runtime wraps `termgo.NewManager` so terminal sessions, PTY activation, history accounting, shell lifecycle setup, multi-connection geometry, realtime attachment, foreground-command metadata, output-activity metadata, execution context, and semantic work state stay inside Floeterm. The released dependency is terminal-go v0.8.7, which classifies the exact `pi` foreground command (including Windows executable suffixes) as the Pi Agent application while rejecting lookalike names. Authenticated local shells also ignore nonce-less prompt-ready and command-finished markers while a foreground command is running, so Agent CLIs such as Pi can emit nested OSC 133/633 semantic zones without replacing the shell-owned command epoch; matching authenticated lifecycle markers remain authoritative. Shell integrations report command lifecycle as `unknown`, `idle`, or `running` plus a safe program basename, monotonic revision, and update timestamp. Bash and Zsh activation starts in `pending` lifecycle mode and becomes `authenticated` only after the session-private bootstrap emits `integration_ready` with the exact in-memory nonce. The nonce is excluded from process arguments, process environment, shared init files, history, logs, terminal output, live subscribers, and terminal-web events. Pending mode accepts legacy lifecycle exits so a shell that cannot install or complete the handshake does not pin a stale remote context forever. After authentication, unauthenticated D/A lifecycle markers, program markers, local-context claims, and final remote pops cannot lower the monotonic remote floor; only a matching authenticated lifecycle exit can do so. Fish, POSIX, and custom providers remain explicitly legacy and never claim authenticated lifecycle. Bash integration preserves a user's valid scalar `PROMPT_COMMAND` as its own syntax unit, including commands with a trailing delimiter such as `history -a; `, while lifecycle hooks keep their execution order, single-execution, and status semantics. Zsh registers both native preexec and precmd hook arrays transactionally and emits readiness only after both registrations are verified; an unavailable or read-only array leaves no partial hook. A user-provided script that was already invalid remains a shell error; Floeterm does not silently normalize or suppress it. While a foreground command remains running, Floeterm separately reports output activity as `unknown`, `streaming`, or `settled`; `settled` means recent terminal output is quiet, not that an agent turn succeeded or the process exited. Execution context separately identifies local or remote location, connection phase, safe remote authority and working directory, and a closed Agent CLI identity. Semantic work reports `unknown`, `idle`, `working`, or `waiting_user` and fences each update to exact context and foreground-command revisions. These context and work snapshots remain untrusted display metadata, including when authenticated lifecycle protects their state transitions; they are not filesystem or authorization boundaries. This is authenticated or explicitly legacy shell-reported command and semantic state plus PTY-derived activity, not an operating-system foreground-process probe or terminal-content classifier; unsupported shell fallbacks remain `unknown`. Redeven configures an 8 MiB retained-byte cap, 65,536 maximum chunks, and 2,048 initial chunk slots; history RPC pages keep the existing bounded chunk and byte limits and preserve first-retained sequence, committed coverage, snapshot end, history generation, reset, truncation, and the exact geometry generation, columns, and rows captured atomically with every output chunk. Redeven maps those geometry fields through the history RPC without reinterpretation; it does not infer a historical grid from the current attachment or from terminal bytes. When retention has evicted a full-screen application's bootstrap state, a forced same-size attach re-applies the PTY size and terminal-go requests `SIGWINCH` from the PTY foreground process group. The resulting complete redraw is committed strictly after the atomic history boundary and arrives through live output; a signal-delivery failure is logged but does not invalidate an otherwise valid attach.

 Realtime terminal traffic uses only the Floeterm `terminal/live_v1` service on a Flowersec named Yamux stream. The first client frame is `ATTACH`; input, acknowledged resize, output batches, geometry changes, session close, and structured errors remain binary frames on that stream. Redeven supplies process permission and session-visibility authorization plus Floeterm's activation callback. It does not register RPC ids 2003 through 2006, keep per-RPC attachment routing, enqueue JSON/Base64 live messages, or silently drop output. The remaining terminal RPC surface is catalog, retained history, clear, delete, stats, and lifecycle/name/foreground-command/output-activity/execution-context/work-state notification control traffic. Type ID 2010 carries name and working-directory metadata plus an explicit product-owned `local_path_capability` object or `null`; Type IDs 2013 and 2014 carry complete foreground-command and output-activity snapshots, while Type IDs 2015 and 2016 independently carry complete execution-context and semantic-work snapshots. Every notification sink binds an immutable control-plane session meta copy and dynamically rechecks the current access-gate channel plus process-launch permission before each synchronous RPC notification write; locked or unregistered channels receive no metadata. Context and work metadata never includes the original command line, arguments, environment, PID, terminal content, or arbitrary Agent identity. A newly created session has no local-path capability. The manager grants or rotates the capability only when the current execution context is local, ready, shell-integration sourced, names the same working directory as the notification, and that real directory remains readable inside the configured filesystem scope. Remote, unknown, mismatched, missing, deleted, denied, or malformed state atomically clears the capability and sends `null`. Catalog and create responses expose only the current optional capability; session close, delete, and cleanup remove it. A missing capability is never reconstructed from display metadata.

Every live stream owns one connection and is removed by Floeterm when the stream ends. Multiple browser pages and multiple concurrently visible mounted views may attach to the same session with different capacities. A KeepAlive view that becomes inactive releases its live attachment and renderer; reactivation opens a new named stream and replays retained history. Floeterm computes one effective PTY grid for the remaining attachments, captures geometry changes against an output-sequence boundary, and sends that geometry to all attachments. The browser reports each active view's host capacity independently while applying the shared fixed grid only after output through the boundary is parsed. Session deletion and natural process exit produce explicit live protocol closure; reconnect opens a new named stream and replays retained history through the new atomic boundary without a compatibility transport.

Floeterm performs shell resolution, environment construction, initialization, argument selection, and PTY startup outside the session lock and owns activation cancellation. Redeven's session delete lifecycle hides a closing session immediately and shares one in-flight delete result across callers; Floeterm closes the attached live streams as part of the terminal session lifecycle. Env App removes a session and its projected capabilities synchronously when a validated lifecycle event reason is `closing` or `close_failed_hidden`; the redundant `hidden` field is informational and cannot weaken that reason-derived revocation. An asynchronous catalog refresh is convergence only and cannot restore authority after a refresh failure. A strict operation with only non-widget participants restores an open, visible, retryable lifecycle and retains its product capability when cleanup fails. Any widget participant atomically promotes the shared operation to widget-owned failure semantics regardless of caller order: failure remains hidden as `close_failed_hidden`, revokes its local-path capability, blocks interaction and catalog projection, and emits the matching lifecycle event so the product can report delayed cleanup without resurrecting a session the widget already removed. Failure-state selection, capability revocation, operation removal, and participant completion resolve under one manager lock. A participant joining after Floeterm has already emitted successful close cannot recreate the removed lifecycle record or capability, and successful completion clears both as a final invariant. Redeven retains no attachment-generation high-water, sink lifecycle token, connection-ownership map, or rollback state machine outside Floeterm.

Terminal recovery verification is layered and automated without starting Redeven Desktop. A deterministic Go fixture covers cleared 0-byte history plus exact 64 KiB, 512 KiB, and 8 MiB retained snapshots with full fixed-generation pagination and exact replayed-byte equality. A production-dist process carrier starts a temporary Redeven Runtime, Local UI, Direct WebSocket/RPC path, real terminal-go session and PTY, then drives the actual Activity and Workbench terminal surfaces across reused and fresh browser contexts. Browser mode and runner-evidence semantics are owned by [Env App upstream web dependencies](env-app-upstream-web-dependencies.md). Before replacing the integrated shell with a quiet fixture shell, the carrier verifies that idle has no command spinner, real `top` changes the title without a spinner after confirmation, and Ctrl-C restores the directory title. Its report records only boolean evidence for those three transitions, never the command or directory title. Chromium's exact WebGL `ReadPixels` driver performance warning is recorded as runner diagnostic evidence rather than an application renderer failure; any other browser warning, error, page exception, request failure, or HTTP failure still fails the carrier. The exact-main pre-push renderer gate runs the 64 KiB and 448 KiB correctness carriers; the fixed-performance gate separately runs 20 shared prepared-history samples for the 64 KiB class with unchanged per-sample and P95 limits. These payloads must reach parser-committed interactive state, report actual retained and fetched bytes, match the seeded history canvas fingerprint, accept a real filesystem input probe, avoid blocking recovery UI, and emit no application renderer, request, response, or page errors. Quick GitHub CI and release workflows do not run the process carrier.

For every non-empty correctness sample, the carrier also clicks the visible Terminal refresh control, requires exactly one new attach, waits for the new parser and render milestones, and compares the refreshed Canvas with the stable pre-refresh evidence at the same grid. It then focuses the replacement renderer, requires no additional attach, compares the focused Canvas again, and only afterward sends the filesystem-backed input probe. This makes refresh rebuild and post-focus `SIGWINCH` behavior part of the real Runtime/PTY/Chromium boundary instead of relying only on mocked Core lifecycle tests.

Redeven consumes terminal-web v0.14.1. Its read-only host-capacity probe and committed-frame fence are the upstream contracts used after replay: an active visible runtime may request a different grid only through the acknowledged resize transport, must wait for the output boundary, and must wait for the final committed renderer frame before exposing interaction or restoring focus. An already attached renderer commits that requested full WebGL frame synchronously in the calling task; renderer attachment and visual-suspension fallbacks remain asynchronous. Historical geometry remains a transient parser fact and never becomes the current shared grid.

The production carrier records runtime, surface, CSS canvas, client, and backing-store dimensions immediately after refresh and again after focus. Overflow fixtures may exceed the 8 MiB ring-buffer cap; they must recover the retained tail, preserve the stable renderer geometry after focus, and accept subsequent PTY input.

## Terminal startup and warmup

Env App hydrates one Terminal session catalog as soon as the protocol client is connected, the environment resource is ready, and process-launch permission is present. The catalog owns the canonical snapshot, refresh single-flight, lifecycle, foreground-command, output-activity, execution-context, and work-state notification convergence, client reconnect epoch, permission clearing, stale-on-disconnect state, and the first-observed timestamp for each continuous remote-opening epoch. All four metadata streams are subscribed at provider scope so metadata-only and unmounted sessions continue to update; early notifications are retained with bounded latest maps until their session appears. Higher revisions may replace current state. Equal revisions are still passed to Floeterm: conflicting execution context fails closed to unknown immediately, is logged without values, and reconciles once to the equal-revision authoritative snapshot; a fence-stale work payload remains rejected without conflict reconciliation. Buffer overflow starts one authoritative reconcile instead of silently losing the oldest metadata truth. Reconcile ownership is connection-scoped: disconnect releases the slot immediately, so a permanently pending request from an obsolete connection cannot block overflow recovery after reconnect. Activity and Workbench consume that snapshot instead of issuing panel-mount list requests, and full create responses use `upsertSession` so a second list round trip is not needed. The Terminal feature chunk remains a separate dynamic bundle; the connected idle path starts a retryable single-flight module/resource preload, while an explicit Terminal intent promotes it immediately.

After the first visible Runtime reaches interactive state, the Env warmup queue may read history pages for running sessions ordered by `lastActiveAtMs`. It uses the released renderer-neutral prepared-history API and a shared byte-bounded MRU cache (`min(32 MiB, warm-core-budget / 8)`). Floeterm's lightweight sessions, history, and preload subpaths keep catalog hydration out of the Terminal runtime graph, and the production build gate rejects any initial static closure that contains TerminalCore, Ghostty, or Beamterm modules. The visible Runtime reads Floeterm's generation-scoped prepared-history outcome after the baseline fence; it never infers accepted/rejected or the independent rebased flag from fetched byte counts. The queue has one background session and one page in flight, yields between pages, caps each preparation by the candidate's actual remaining-or-evictable budget, skips history when `saveData` is enabled, and lets an interactive selection promote an existing task without duplicating requests. If another session already owns a physical history RPC that cannot be cancelled promptly, the interactive target abandons its queued seed and uses normal recovery instead of waiting behind background work. Warmup is cancelled on inactive or hidden surfaces, disconnect, environment or permission changes, delete, clear, and history invalidation. It never creates a Core, attaches a session, resizes a PTY, subscribes to live output, or changes terminal attachment ownership. Dormant sessions therefore remain metadata-only and do not incur PTY startup or retained-live memory. Activity and Workbench share only the validated seed; their Core, focus, geometry, and attachment remain surface-local. Structured UI diagnostics expose catalog, preload, sidebar, create, and warmup phases with pseudonymous session references, prepared-history generation, byte/page counts, and actual history reset/truncation flags; a generic prepared-history rebase is not itself reported as truncation. Terminal list and create debug projections retain only aggregate counts and field-presence booleans. Diagnostics never record real session IDs, paths, remote identity, context, commands, or terminal content.

# Boundaries

Compatibility depends on these transport and terminal interfaces staying aligned across released versions. Redeven compatibility epoch 8 requires Desktop and Runtime v0.10.0 or newer because Local UI exposure is now a startup and status contract shared by both processes. Replacing or bypassing the published contracts can break control and data channel behavior, liveness teardown, bounded RPC dispatch, plaintext network admission, sparse history coverage, command lifecycle events, or terminal session lifecycle. ConnectArtifact v1, E2EE record framing, Yamux frames, and Redeven business RPC payloads remain owned by their existing upstream or product contracts; Redeven business concepts remain outside Flowersec. History and session diagnostics are observability signals only: neither Redeven nor Floeterm may use session count to reject creation, automatically close a PTY, or pause an existing session. Frontend renderer hibernation is not a runtime lifecycle transition: disposing an inactive `TerminalCore` must leave the terminal-go session and PTY running, and later snapshot or paged-history recovery resumes only the visual consumer.
