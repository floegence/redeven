# Summary

Floeterm terminal-go owns each PTY, native Ghostty VT, geometry, controller epoch, input encoding, semantic history, clear/reset, and atomic Presentation. Redeven maps permissions, session metadata, and Activity/Workbench placement around that actor; browser views consume bounded semantic streams and never become a second terminal state machine.

# Contract

The runtime wraps `termgo.NewManager` so one terminal-go `SessionActor` owns each PTY, native Ghostty VT, canonical geometry, controller epoch, input encoding, semantic history, clear/reset, and atomic Presentation. Redeven supplies product permission and visibility admission, session metadata projection, and lifecycle integration; it does not parse terminal bytes or keep another history. Shell integration reports authenticated or explicit legacy command lifecycle, output activity, execution context, and semantic work as revisioned display metadata. The private bootstrap nonce never reaches arguments, environment, shared files, logs, output, live subscribers, or terminal-web. Those snapshots are not filesystem or authorization boundaries. Bash preserves a valid user `PROMPT_COMMAND` as its own syntax unit, Zsh installs both hook arrays transactionally, and unsupported shells remain explicit legacy sources.

Realtime terminal traffic uses only Floeterm `terminal/live_v1` on a Flowersec named Yamux stream. Attach, structured input, bounded paste, acknowledged resize, geometry-bound atomic interaction, atomic Presentations, geometry, session close, and structured errors use Floeterm framing. A paste is fully reassembled under the transport budget before one SessionActor admission, where the native VT owner applies the current bracketed-paste mode and newline encoding. Redeven does not register legacy live RPC ids 2003 through 2006, keep per-RPC attachment routing, enqueue JSON/Base64 output, or silently drop events. Catalog, semantic history, actor-owned clear, delete, and lifecycle/name/foreground-command/output-activity/execution-context/work-state controls remain bounded RPC operations. History requests separate scroll distance, canonical viewport rows, and compact transport chunks. A direct target offset is fenced by the server snapshot identity; every continuation remains on the same browse or search lane and is assembled before projection. History and clear bind to the current connection, transport generation, attachment, and process permission; stale generations have zero effect.

Every live stream owns one attachment and is removed when the stream ends. Multiple browser pages and simultaneously visible Activity and Workbench views may attach to one session. All receive the same advancing Presentation. Only the current controller attachment may write input or propose canonical geometry. Selecting a same-principal view focuses its local input bridge immediately and starts explicit activation for controller-state convergence. A real text, key, or paste interaction from that view does not wait for the activation acknowledgement: Redeven sends its latest untransformed grid and input together, and terminal-go validates authority, atomically transfers ownership, applies and captures the geometry, natively encodes the interaction, and writes it in one actor ordering window. The outer display mode and selected Workbench widget gate interaction, while observer resize only records local intent and cannot steal control. Stale generations, stale epochs, cross-principal requests, and rejected atomic interactions have zero PTY effect. Resize success means terminal-go applied the geometry and emitted a matching Presentation, not that Redeven replayed a stored frame. Disconnect opens a new named stream; ordinary resize never detaches or auto-reattaches.

Floeterm performs shell resolution, environment construction, initialization, argument selection, and PTY startup outside the session lock and owns activation cancellation. After merging the host environment with Redeven's `EnvProvider`, terminal-go v0.19.2 preserves `LC_ALL`, `LC_CTYPE`, `LANG`, and other inherited locale variables exactly as supplied. Only when all character-locale selectors are absent does terminal-go run a short, activation-cancellable `locale -a` probe whose output never enters the PTY; it adds only `LC_CTYPE=C.UTF-8` or `LC_CTYPE=C.utf8` when that exact neutral UTF-8 locale is listed. A missing, failed, timed-out, or unsupported probe leaves the environment unchanged. Redeven does not own a second locale default, repair invalid inherited values, or filter real shell output.

Redeven's session delete lifecycle hides a closing session immediately and shares one in-flight delete result across callers; Floeterm closes the attached live streams as part of the terminal session lifecycle. Env App removes a session and its projected capabilities synchronously when a validated lifecycle event reason is `closing` or `close_failed_hidden`; the redundant `hidden` field is informational and cannot weaken that reason-derived revocation. An asynchronous catalog refresh is convergence only and cannot restore authority after a refresh failure. A strict operation with only non-widget participants restores an open, visible, retryable lifecycle and retains its product capability when cleanup fails. Any widget participant atomically promotes the shared operation to widget-owned failure semantics regardless of caller order: failure remains hidden as `close_failed_hidden`, revokes its local-path capability, blocks interaction and catalog projection, and emits the matching lifecycle event so the product can report delayed cleanup without resurrecting a session the widget already removed. Failure-state selection, capability revocation, operation removal, and participant completion resolve under one manager lock. A participant joining after Floeterm has already emitted successful close cannot recreate the removed lifecycle record or capability, and successful completion clears both as a final invariant. Redeven retains no attachment-generation high-water, sink lifecycle token, connection-ownership map, or rollback state machine outside Floeterm.

Semantic terminal verification is layered and automated without starting Redeven Desktop. Go tests cover permission admission, actor-owned clear, same-size quiet reattach, session lifecycle, and real PTY shell integration. Browser tests cover one canvas, semantic input, IME, selection/copy, search, history, theme, cursor-facing geometry, links, and resize. A production-dist carrier starts a temporary Runtime and real PTY, then drives Activity and Workbench across reused and fresh Chromium contexts. It verifies clear, bounded history projection, controller transfer, refresh, twenty `top` resizes under 150 ms, DPR backing, nontransparent canvas paint, and zero page, console, request, response, or semantic errors.

For every product carrier sample, refresh forgets only the view attachment, preserves the existing semantic canvas, and requires a new current Presentation even when geometry is unchanged. The carrier then proves real input still reaches the PTY. This is the Runtime/PTTY/browser boundary rather than a mocked renderer lifecycle.

Redeven consumes terminal-web v0.19.2. Each mounted view uses one `RendererSurface`, one `TerminalInputBridge`, one `HistoryViewportController`, and one isolated `HistorySearchController` over complete semantic Presentations and atomic history viewports. Host bounds, DPR, view-local palette, typography, occurrence-level search decoration, cell-aware word and row selection, pointer-captured edge clamping, IME anchor, bounded semantic-frame cache, and history projection are browser concerns; PTY state, frame geometry, cursor, inverse cells, grapheme width, hyperlinks, graphics, snapshots, and history remain terminal-go facts. Hidden keep-mounted views fence their canvas until a render commit matches current host bounds and DPR, preventing browser scaling of an old backing store. The browser has no Ghostty WebAssembly, TerminalCore, checkpoint worker, Beamterm renderer, raw replay fallback, predicted echo, or Redeven-owned history state machine.

The production carrier records runtime, surface, CSS canvas, client, and backing-store dimensions immediately after refresh and again after focus. Overflow fixtures may exceed the 8 MiB ring-buffer cap; they must recover the retained tail, preserve the stable renderer geometry after focus, and accept subsequent PTY input.

## Terminal startup and warmup

Env App hydrates one terminal session catalog after protocol connection, environment readiness, and process permission. The catalog owns canonical session metadata, notification convergence, connection epoch, permission clearing, stale-on-disconnect state, and bounded early latest values. It remains renderer-free and does not warm browser VT state. Activity and Workbench consume the same catalog while each mounted view owns only its attachment, semantic canvas, palette, focus, selection, and local history projection. Permission loss clears catalog and local-path capability immediately and prevents stale notifications from restoring them.

History is requested only by a mounted semantic Runtime when its user scrolls or searches outside the latest Presentation. Each request is bound to the current connection, transport generation, attachment, session, content epoch, geometry generation, lane, and snapshot frontier. The actor captures one complete canonical viewport at one cut; compact chunks are reassembled and validated before one atomic projection. Ordinary live output updates the latest Presentation and total-row summary without replacing the immutable visible history viewport. Clear/reset, geometry or content-epoch change, detach, permission loss, and structural snapshot failure return the view to the latest complete Presentation. Each view keeps an isolated semantic-frame cache for its terminal session with a 4 MiB extra-frame ceiling and no global cache limit. A normal scroll plans a window up to 10 viewports; a sustained same-direction burst plans up to 20 viewports. Both remain capped by the retained history, 4,000 rows, and an 85% cache target derived from measured row size. A hidden kept-alive view retains validated immutable windows so returning to a static terminal does not force a cold history RPC; revision, content epoch, geometry, transport generation, and snapshot lineage still fence every reuse. The browser keeps no shared prepared-history cache, background warmup queue, raw-byte replay, parser snapshot, or second scrollback authority. Activity and Workbench views may independently browse and search without changing the PTY, canonical geometry, controller, or another view. Diagnostics retain aggregate phase and field-presence facts only and never record session identifiers, paths, remote identity, commands, or terminal content.

# Boundaries

Terminal lifecycle depends on the published Floeterm and Flowersec interfaces. Redeven must not parse terminal bytes, keep another history, replay raw output, add browser VT/WASM fallbacks, or introduce a second attachment or controller owner. History and diagnostics remain observational and never become admission limits.
