# Summary

Env App keeps terminal and Activity/Workbench surfaces thin over published Floeterm and Floe components. A mounted view owns only its semantic projection and local interaction state; Floeterm owns PTY facts and Floe owns shell, selection, KeepAlive, focus, and layer mechanics. Lazy loading and recovery preserve those ownership boundaries while keeping existing surfaces mounted and interactive where policy allows.

# Contract

File preview surfaces carry an internal `surface` contract that defaults to `main`. Desktop floating preview hosts pass `window` through every renderer, mapping product-owned toolbars, reading areas, controls, tables, media hosts, and loading/error states to Floe's published window background, foreground, titlebar, and border tokens. Workbench panels, embedded pages, and mobile Dialogs pass `main`; PDF paper, DOCX pages, image/video/audio content, Monaco canvases, terminal output, and other third-party renderers retain their own palettes while the visible host expresses the window boundary. The window remap is scoped to the soft-neumorphic surface and derives card, muted, accent, and border semantics from the published window tokens, so standard and high-contrast surfaces keep their existing behavior.

Terminal surfaces import Floeterm's semantic, live, and sessions entry points. `TerminalSessionRuntime` is a thin adapter around one `RendererSurface`, one `TerminalInputBridge`, one live attachment, and generation-bound semantic history and clear controls. Activity and Workbench reuse that runtime and the same controller/observer contract. The catalog stays renderer-free, dormant sessions stay metadata-only, and the initial build graph rejects terminal live or renderer modules. The complete terminal interaction contract is [Workbench terminal interaction](../ui/workbench-terminal-interaction.md).

Floeterm terminal-web v0.19.2 publishes the semantic Presentation validator, complete history viewport controller, isolated occurrence-level history search controller, compact continuation transport, `RendererSurface`, `TerminalInputBridge`, live codec with geometry-bound text, key, and paste interactions, session metadata helpers, shell-integration display normalizers, theme catalog, and input intent types. A history viewport is one atomic server snapshot with canonical width and height even when its compact payload crosses multiple transport chunks. The Presentation preserves explicit ANSI indexed/RGB colors, inverse-cell state, cell attributes, grapheme width, hyperlinks, cursor state, graphics, geometry, and semantic history metadata. View-local default foreground, background, cursor fallback, search decoration, selection, typography, and DPR are applied only while painting; palette changes repaint the latest Presentation without changing PTY state or sequence. Clipboard copy stays on the browser's synchronous copy event, while paste uses the bounded semantic paste channel instead of ordinary text input. Repeated browser clicks remain view-local renderer gestures: double click selects one semantic word and triple click selects the logical row without splitting wide cells. Selection begins only on a valid grid cell; after the host captures the pointer, out-of-grid updates and release clamp to the nearest edge cell so fast drags remain continuous without automatic history scrolling. Redeven adds product placement, permission mapping, local-path capability, file preview, safe external-URL activation, and Activity/Workbench chrome, but it does not parse PTY output, predict echo, or infer terminal state.

Terminal diagnostics are view-local and content-free. They project attachment lifecycle, Presentation and geometry sequence, semantic history revision, resize settlement, and structured Floeterm error codes. Debug Console never retains terminal input, output, session id, connection id, path, raw server message, or raw failure cause. Sequence, geometry, and lifecycle generations remain distinct, and stale events cannot commit into a newer connection.

The catalog adapter is a separate static module from Floeterm live transport and rendering. Initial catalog hydration cannot pull the semantic renderer or live codec into the Env bootstrap. Semantic history is queried lazily by a mounted view. Each view owns its scroll target, serialized request lane, isolated 4 MiB session cache, selection, and projection; search uses Floeterm's separate server frontier and never replaces the browse frontier. Validated history windows remain warm across kept-alive view switches and adapt from 10 to 20 viewports during sustained same-direction scrolling, subject to retained-history, 4,000-row, and byte-budget caps. Connection-generation change, content epoch change, geometry change, clear, delete, permission loss, and disposal invalidate those resources, while ordinary live output advances in the background without replacing a visible immutable history viewport. There is no browser checkpoint, prepared raw history, replay queue, or warm-core VT cache.

Each `TerminalSessionRuntimeStatus` belongs to one mounted view. Activity and Workbench may fail or reconnect independently while still consuming the same actor-owned Presentation. A selected view explicitly activates the grid measured from its untransformed host layout content box before focus or input; an activation rejection remains the precise fail-closed error and admits no PTY write. The outer display mode and Workbench selection gate that interaction, so a hidden kept-alive peer cannot retake controller ownership. The runtime root reports `aria-busy=true` only until the first valid Presentation is painted; later view-local history projection remains interactive. Permission, protocol, actor, and semantic validation errors stay explicit instead of being reclassified from message text.

Env App keeps only bootstrap, access, protocol, and shell chrome in the initial module. Activity surfaces, Workbench, Terminal, Monitor, Files, Codespaces, Ports, Flower, Settings, Plugins, Debug Console, audit, file browser, and file preview hosts are loaded through feature boundaries when activated. Flower providers are scoped to the surfaces that need them, so a connected shell does not initialize AI settings, model catalogs, or thread lists by default. Feature CSS follows the same boundary: Iosevka loads with Terminal, shared Flower and chat styles load with Flower entry points, and the upstream KaTeX stylesheet and fonts load with Markdown preview. Markdown math retains KaTeX's `htmlAndMathml` output so the official feature stylesheet presents one visual formula while preserving the assistive MathML representation.

Activity navigation does not replace the Activity Shell or change its outer provider structure. `ActivityAppsMain` is the lifetime owner for Activity surfaces: a surface mounts on first activation and remains mounted but hidden while another Activity surface is active. This preserves file browser path, expanded directories, filtering, view mode, selection, scroll position, and equivalent local state in Terminal, Monitor, Flower, and other registered Activity surfaces. Activity and Workbench are themselves two lazily visited views in one `KeepAliveStack`; after first activation, switching display mode changes visibility and activation after paint without destroying either view. Activity navigation, display-mode navigation, and Workbench widget activation therefore share the same lifetime rule: lazy before first visit, stable DOM/provider/data-flow identity after first visit.

`FloeRegistryContributions` projects launchable, Activity-pinned plugin entries by stable component id. Retained ids preserve the existing `ActivityAppsMain` KeepAlive view, while removal serially awaits the product contribution's exact surface close before unregistering. Activity Bar and Workbench Dock item context-menu requests preserve the concrete button and viewport pointer position; Redeven renders the product action with `SurfaceFloatingLayer`, which projects Workbench menus into the owning surface instead of using viewport-fixed coordinates.

Connection recovery preserves those lifetime owners. Activity and Workbench each mount the same `ConnectionRecoveryView` once at their content root while their existing page DOM remains mounted. The underlying content container becomes `inert`, pointer-disabled, and `aria-hidden`; Terminal, Files, Monitor, Workbench widgets, and other surfaces do not own separate connection curtains or continue accepting stale input. The recovery presentation derives a fixed applicable-step timeline, exact completed-step percentage, real attempt counts, and only known retry timestamps from the immutable snapshot. Successful recovery remains visible for 1.5 seconds before the snapshot returns to idle and the original surface becomes interactive again. Terminal failure retains the window, focuses an alert heading, keeps technical details collapsed by default, and exposes only actions present in the Desktop snapshot. Raw HTTP status text is diagnostic detail rather than primary recovery copy.

The released floe-webapp selection controller separates immediate visual selection from committed content. Env App opts the Shell into UI-first Activity selection, uses after-paint activation for `ActivityAppsMain`, and uses another UI-first controller plus after-paint `KeepAliveStack` activation for Activity/Workbench mode changes. User input uses the delayed transaction path; initialization, restore, permission fallback, and other canonical corrections may commit synchronously. Persistence runs from the committed state rather than from a visual preview. Navigation does not suspend hidden surfaces, stop subscriptions, hibernate terminal cores, refetch warm content, or recreate providers; only visibility-dependent focus, resize, scroll restoration, viewport movement, and measurement may run after the target content has painted.


The local bootstrap reuses the access status returned by `getLocalRuntime()` instead of issuing a second access-status request. Production builds enforce compressed initial-resource budgets of 602 KiB JavaScript, 122 KiB critical CSS, and 720 KiB total for each emitted document. The CSS budget includes a bounded margin for the Node/zlib versions used by local and hosted release builders. Each document includes all its static shared imports in its own budget; independent windows are not summed into a single load. The main and access documents must exist in the emitted manifest and on disk. The budget check also rejects initial HTML references to Markdown, KaTeX, Mermaid, Monaco, Excel, PDF, Shiki, Flower, feature assets.

Terminal stream lifetime and native autofocus are separate contracts. A kept-alive hidden surface may retain its attachment only while product policy keeps that view active; an observer never writes input or geometry. Its canvas stays hidden while the host has no usable bounds and becomes visible only after one atomic render has matched the current host content box and DPR, so an old small bitmap is never stretched during tab activation. The Floe mobile keyboard may leave the semantic textarea unfocused. Every asynchronous attach, activate, resize, history, search, clear, and repaint path checks the view disposal and connection-generation fences, so an unmounted surface cannot reopen a stream or apply a stale result.

Floeterm semantic logger callbacks are strict content-free product adapters. Redeven emits stable event and error codes with numeric or boolean metadata, never raw `Error` objects, upstream messages, terminal content, or encoded content. Console privacy tests reject both a unique raw secret and its encoded form.

Renderer validation keeps distinct evidence boundaries. The built-dist shell smoke serves only production Env App assets and proves a nonblank root, expected title, content-hashed JavaScript and CSS, and no framework or browser errors; it does not claim terminal coverage. The semantic terminal carrier separately starts a temporary production Redeven Runtime and drives the real Local UI, Direct transport, terminal-go SessionActor, PTY, Activity, Workbench, `RendererSurface`, and `TerminalInputBridge` path in headless Chromium. It verifies one semantic canvas, canonical frame geometry, DPR backing, nontransparent paint, actor-owned clear, history projection, controller transfer, refresh, and twenty `top` resizes. Automated gates do not start Desktop and do not claim packaged Electron evidence.

The carrier uses reused and fresh browser contexts, opens Activity and Workbench on the same session, and proves their Presentation sequence, content epoch, and frame geometry converge. Refresh preserves the existing canvas and receives a new Presentation even at unchanged geometry. Input probes use the real PTY, and any page, console, request, response, or semantic error fails the sample.

Dialog guidance follows [dialog content placement](../ui/dialog-content.md). The published body-only description API owns placement and accessible association; product adapters do not restore header subtitles.

Input controls follow the shared [input focus boundary](../ui/input-focus-boundaries.md). Floe owns the CSS contract; Redeven marks custom compound controls without duplicating focus styling.

# Boundaries

Redeven supplies product placement, permission mapping, local-path capability, and localized chrome. It must not parse terminal output, predict echo, own history or renderer state, recreate shell token/layer/focus state machines, or replace a retained surface with a second recovery curtain. Browser validation and semantic terminal carriers prove this adapter boundary; packaged Desktop evidence remains a separate gate.
