# Summary

The market discovers passive template evidence. Redeven acquires exact originals through Desktop or Runtime before deployment.

# Contract

## Discovery and acquisition
The existing `redeven-plugin-market` Worker discovers public repositories tagged `redeven-service-template`; no separate registry/repository is required. The published SDK finds root templates or direct `templates/<name>` entries. The default branch tracks updates; changed directories require a higher revision. Changed bytes at the same revision are rejected. Confirmed unavailability is recorded; observation failures retain verified evidence. Classification grants no execution trust. Reserved interactive-desktop capabilities require every original byte and mode to match the published official manifest; immutable source metadata preserves that authorization across package upgrades, and reopening verifies its digest. New privileged definitions require an upstream release.


`GET /managed-web-service-templates/market-catalog` returns local cache with read permission; explicit/open-discovery refresh uses POST and full permission. The product reads a complete ordered generation, validates identity/presentation, rejects redirects, regressions and incomplete pages, then atomically replaces its cache. Failure preserves prior evidence. Environment changes fence UI responses. Official and community entries use the same verified catalog and pinned deployment flow. Discovery is the default entry and initially includes every deployment type. Official, Community and My templates are explicit source views. My templates contains accepted Git sources and user-created templates; embedded definitions are excluded from browsing/new deployment entry points. Embedded published bytes remain solely for legacy instance resolution and exact-source runtime-profile authorization. No instance or source binding is rewritten. Remote discovery never overwrites a builtin template or silently upgrades an installed instance.

Market Deploy opens configuration immediately and automatically acquires the immutable, owner-scoped 15-minute source review also used by imports. It does not open a separate review dialog or require Continue to deployment. Source identity, digest and execution details remain expandable in configuration; required notices and final Deploy authorize execution. The market selection pins numeric repository ID, commit SHA and directory digest through Desktop transfer or remote acquisition. Runtime independently verifies originals with the published reader. Anonymous pinned acquisition uses the upstream v0.8.2 reader's exact-commit `codeload.github.com` archive path in both Desktop and Runtime; it does not consume GitHub REST quota. The selected repository ID is retained as expected evidence, while commit metadata, every directory byte and executable mode must match the pinned digest. Archive bounds, portable paths, collisions, LFS and unsupported entries fail closed in the upstream reader; no extraction, automatic retry, API fallback or moving-ref substitution occurs. Credentialed and unpinned requests retain the GitHub API path with API-only ephemeral credentials and rejected redirects. Private tokens remain request-scoped. Neither discovery, inspection, file review nor install preparation saves executable sources or runs lifecycle actions. A market deployment continues directly from source review to the existing install form; the final request atomically commits source acceptance, source binding, service, forward and operation receipt. Receipt reconciliation never blindly replays an uncertain install. Source/preflight failures and unavailable prerequisites remain visible in the same drawer with explicit retry. Existing instances and pending requests block submission visibly. Retry of an expired source retains the exact market identity, selected release and draft, including after a rejected submission. Cancel and environment changes fence acquisition. Fixed buttons carry busy state without loading text or reserved feedback rows; errors overlay above the footer. Final submission immediately creates a visible progress row before the receipt arrives.

## Marketplace browsing
Redeven consumes the published metadata without adding a second registry, GitHub repository, local format or name-based taxonomy. Categories are All types, Host, Container and Docker Compose. Semantic categories require an upstream format/publication contract; names never imply taxonomy.

Search combines whitespace-delimited terms, normalizes Unicode width/case, and covers displayed identity, all published localization names/descriptions, document identity, repository/path and default release. Source and deployment facets compose with search; counts reflect the current source/search before deployment filtering. Empty results offer a reset to complete discovery. Refresh replaces passive evidence without clearing the query, category or requested identity, including successful empty results. Environment ownership fences pending responses. Stale/error details use the fixed refresh control's tooltip and live description, never a new row; loading, warning and retry follow [page continuity](../ui/page-loading-continuity.md). Saving or importing a template opens My templates with clear filters.

The source navigation, search/actions and deployment facets occupy separate rows. Categories wrap at narrow widths, names wrap, descriptions use two lines, and independent list/detail scrolling keeps deployment reachable on desktop. Remote details show only published evidence (deployment, revision, release, platforms, immutable source link); access mode and execution settings appear after review, never as unexplained empty placeholders. Source grouping uses Official/Community instead of labeling every remote entry GitHub. Shared Floe controls retain keyboard/focus behavior; this layout is a product adapter.

Acceptance covers four official entries without bundled duplicates, composed search/facets, library creation/import, review ownership, admission and environment fences, locales and 320–1440px geometry. Runtime tests cover legacy lifecycle and capability authorization.

# Boundaries

The upstream reader owns acquisition, parsing, compatibility and byte validation. Redeven owns UI, authorization and lifecycle execution. Publication and retained source formats follow [managed service templates](managed-web-service-templates.md).
