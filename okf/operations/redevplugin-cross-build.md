# Summary

Redeven prepares target C compilation and archiving alongside Rust before building the exact published ReDevPlugin source crate. macOS builds Linux static PIE with pinned Zig and the existing Rust LLD wrapper. `scripts/redevplugin_build_toolchain.json` pins Rust 1.98.0, Zig 0.16.0, official archive checksums and build-input files.

# Contract

The unified preparer selects the actual builder and requested target, prepares Rust, downloads Zig only when missing with HTTPS/checksum/bounded retries, then compiles C, archives it, links it into a Rust program and validates the resulting executable. Darwin native uses Apple tools; Linux native uses its C compiler and static libraries. A failed probe prevents costly package compilation.

macOS maps Linux amd64/arm64 to x86_64/aarch64 musl. Target-specific cc-rs CC/AR settings use private wrappers; the CC wrapper removes only the exact Rust triple injected by cc-rs, supplies Zig's target, PIC and disables Zig's implicit undefined-behavior instrumentation. Rust LLD remains responsible for static PIE; existing ELF architecture, interpreter and dynamic dependency rejection stay authoritative. No ambient target GCC or installed PATH Zig is assumed.

Desktop preflights before copying source or building UI/Go. Staging independently invokes the same owner. Development Cargo identity binds exact published crate digest, compiler versions, Zig archive/binary, target flags, wrapper and validation inputs. Desktop package-cache v2 binds host, target, input inventory, release manifest and source identity; older disposable entries rebuild. `REDEVEN_REDEVPLUGIN_TOOLCHAIN_CACHE` selects an absolute tool cache; `REDEVEN_TOOLCHAIN_OFFLINE=1` requires cached tools. Rust's narrower offline setting remains available.

Release-cache pruning recognizes only the namespaces generated by the release-source cache-key owner. It never descends into sibling toolchain, Cargo, source-package, plugin-manifest or unknown cache namespaces, in either startup or package-preparation mode. Toolchain preparation owns its temporary download, extraction and probe directories and removes them on completion or cancellation. This prevents another package request from unlinking an active Zig download or compiler input; disabling release temporary-file cleanup alone does not provide that protection.

Preparation distinguishes unavailable tools/cache, network acquisition, source compilation and artifact validation. Shipped locales provide the concise summaries; diagnostics retain original output. Compiler errors never trigger a network retry. Cancellation/timeout terminates the task-owned command group, escalates after two seconds, waits for close and cleans temporary state. Target replacement begins only after a complete package is prepared. Helper/package uploads use the existing bounded transfer budget rather than the short command budget. Checksums, signed release consumption, SBOM, provenance and product signing remain required.

# Boundaries

Redeven owns compiler preparation, target packaging, cache isolation and product signing. Published ReDevPlugin owns execution, containment and Worker contracts; cross-compilation cannot qualify an upstream runtime defect. Native target execution and the production Desktop update path require separate acceptance; architecture emulation and main-process harnesses do not certify native containment or GUI interaction.

# Evidence

November 4, 2026: three deterministic cases reproduced pruning of open Zig archives. Namespace-limited pruning preserved tool/Cargo/source/manifest/unknown owners while retiring obsolete release assets.

Unmocked Desktop update built checksummed published 3.15.0 from empty per-target caches on macOS ARM64 with concurrent 100-ms pruning, validated static PIE/signature/evidence, installed and reached runtime_ready on native AMD64 Linux and ARM64 Docker. Repeat builds verified cache reuse; offline/refused/canceled paths preserved installed bytes/processes and removed transient tools. These are production-method tests, not GUI clicks.

Native Worker filesystem/HTTP/WS/TCP/UDP and cancellation/isolation checks passed; emulated AMD64 containment/inventory failed and cannot substitute. Published 3.15.0 duplicate TCP-close revocation remained unaccepted despite resource closure; [performance evidence](redevplugin-performance-qualification.md) retains it. Later published Floe 0.90.4 browser/Desktop/integration and ordinary hooks passed after rebase.
