# Summary

Flower authors through released ReDevPlugin CLI/SDK and version-matched guidance. Plugin Center owns authoring conversations; ordinary Flower keeps its tools/navigation. Canonical streaming, approvals and dispatch stay shared.

# Contract

## Guidance and upstream workflow
Only authenticated active plugin-creation conversations discover/activate `redeven-plugin-authoring` and `plugin_author_*` tools. Ordinary model requests omit both; Settings may browse/disable the skill. Activation/dispatch retain normal permissions. Installation coordinate follows imported ReDevPlugin, without another pin.

Preserve the user's project identity/data contracts; new projects choose the smallest suitable released template. Pure Web surfaces may use declared private resources without a Worker. Worker execution requires published WASM tooling and verified development runtime. Missing capabilities remain explicit requirements.

Released ReDevPlugin owns doctor diagnostics, generation/typecheck/build/business-test/package pipeline, watching, persistent development roots, candidates, fresh session authority, connections review and runtime preparation. Flower consumes actual reports, never duplicates validators/watchers/lifecycle/supervisor. Doctor/package/business evidence is not browser or WASM proof; qualify requested journeys and state verified boundaries.

Candidates build while current frame/drafts remain; Apply/reload creates a fresh frame and needs saved application state. Failed builds retain valid preview. Persistent roots survive restart; reset is explicitly destructive. Connections retain destination review/grants/revocation.

## Draft and conversation ownership
Each draft owns one canonical Flower conversation and opaque platform workspace. Ordinary paginated/live inventories exclude all owned threads, including deleting/deleted records, independently of title/directory/backend availability; pagination crosses hidden pages. Reconnect empty baselines preserve embedded selected detail/composer/live updates. Explicit references to ordinary threads never adopt/delete them.

Use ordinary composer Send, attachments, approvals, streaming and dispatch; no direct-creation intent/fallback prompt. `/plugin` navigates before model configuration and never becomes a turn when unavailable. Initial reference attaches only to the first new-thread submission and clears on acceptance.

Authenticated runs resolve the `plugin.author` profile into the shared `work_binding` canonical `ModelContextSnapshot` section; Floret compares/adopts chronologically. Unchanged guidance is not another user reference; ordinary threads omit it and persisted history stays intact.

Draft turns/input/approval/compaction/goal continuations use authenticated environment HTTP, never synthetic Local UI authority. Owner is authenticated user/environment. Freeze exact canonical create request before creating thread; bind ownership before root settings. Reused IDs cannot adopt unrelated threads/projects. Reopen/delete reconciles interrupted settings admission under that same request without replaying a user turn.

Only platform-resolved authenticated managed source joins filesystem scope; preserve private task-file isolation and ordinary file/terminal effect approvals. Other projects/platform state/task directories stay excluded. Admitted source work survives disconnect under original user/environment/current tool policy without reactivating expired platform sessions. Explicit Retry binds current authenticated channel authority while preserving model/options and failed record. Build/capture may finish offline; installation readiness is session-bound and re-reviewed on reconnect. Acceptance covers post-disconnect tools/context refresh, retry and long history.

`plugin_author_get_status`, initialize, rename, build and capture require the owned thread. Initialize persists selected title; Flower chooses concise localized names unless user supplied one. Rename binds revision/owner/thread; source display name/build is separate from installed authority. Status retains structured metadata despite long-log truncation. Legacy unnamed history uses verified package names without rewriting titles.

Changed release bytes need higher source SemVer, preserving identity. Build/capture use released Host inspection against formal installation, returning `ready_for_install` and structured `installation_check` even with truncated logs. Rejected packages need repair; same-version preview iteration remains allowed. Readiness cannot install/grant/change frames. Build is a normal Floret command effect; retained stages distinguish passed/failed/interrupted/not-run. Packaging alone proves neither business correctness nor browser behavior.

For iterative work, guidance requests a small useful runnable version and early validated build; first artifact may auto-apply, later updates stay explicit. This is guidance, not guaranteed latency or scheduling. Unrelated demos, untouched template captures or unlabeled fabricated data are not progress. Simple edits need no milestone build; preview never replaces completion/acceptance. [Build visibility](../ui/plugin-build-visibility.md) remains a proposal, not shipped events/UI.

Deletion durably freezes admission, reconciles pending create, cancels/deletes the owned thread, then closes/removes platform workspace. Interrupted cleanup resumes its stage. Unknown formal install outcomes must reconcile before removal; installed instances remain. Legacy direct deletion follows the same review/cleanup.

## Visual revision and delivery
Canvas comments enter the same thread through durable outbox with explicit text and bounded reviewed-artifact context. Preserve unrelated composer content. Active runs queue without stopping Flower. Comments supply only their visual context; package repair uses no synthetic workspace references. Dispatch waits for handler/storage generation; blocked/unknown decisions cannot launch a turn. Rejected/uncertain submissions retain ordinary recovery. Model reads current source via status; text/selectors are untrusted observations. Stale selectors never authorize blind edits/install; changed source may need reconciliation.

Before the first runnable milestone, author a purpose-specific self-contained SVG at `ui/assets/plugin-icon.svg`; locked build renders/packages 256×256 PNG and SVG, with `presentation.icon.path=ui/assets/plugin-icon.png`. Configured tests verify alignment. Missing/invalid assets, stock placeholders or disguised rasters fail delivery. Inspect 16/24/32px in both themes; no active/external SVG resources. Preserve existing icon identity on unrelated edits.

This is Flower delivery policy, not global admission: platform still accepts PNG/WebP icons and rejects SVG surface icons. Consume verified raster evidence. Model-instruction/generated-artifact tests cover policy; shared conversion or SVG admission requires upstream release.

Authorized local project steps use ordinary tools; final sources/packages go to user's destination. Plugin Center inspects exact bytes for installation review/confirmation. Install approval, execution grants and auto-update eligibility remain separate. Ordinary plugin packages need no publisher trust/signature admission; platform/runtime releases retain verification. No second approval wait, Floret bypass, manual timeline mutation or audit-to-activity conversion. Unknown effects reconcile; requested approvals wait for canonical resolution.

# Boundaries

Flower cannot write registry rows, mint bridge tokens, expose assets through product routes, bypass inspection/source policy, grant broker-external authority or call business adapters before platform context construction. Fix shared mechanics upstream and consume releases. Development runtime evidence never substitutes for signing/packaging.
