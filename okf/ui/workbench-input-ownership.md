# Summary

Workbench input ownership is declared through explicit marker contracts so canvas zoom, local scrolling, pointer actions, and text selection remain distinguishable. A selected widget boundary does not automatically own wheel input, and local-scroll regions must declare their role rather than relying on incidental DOM structure. These contracts let the canvas remain predictable while nested product surfaces preserve native interaction.

# Contract

## Mechanism

Wheel ownership uses exported local scroll viewport props that set `data-floe-canvas-wheel-interactive="true"` and a local-scroll role. Layout-only regions can declare a non-interactive wheel role. Text selection surfaces use separate marker props and do not receive wheel ownership unless combined with local scroll viewport props. Action surfaces declare their own marker so clickable controls can remain interactive inside widgets without becoming text selection surfaces. Terminal shortcuts such as panel-local search and session switching stay inside the owning `TerminalPanel` event tree; they do not create a window-level owner or widen wheel, selection, copy, or widget activation. Terminal renderer, input, history, and controller semantics are owned by [Workbench terminal interaction](workbench-terminal-interaction.md); this concept owns only their routing through Workbench markers and panel focus.

Terminal session selection uses the shared UI-first selection controller and a Floe Sidebar session list. Pointer down may preview the target, while click and keyboard selection request the same transaction: the active sidebar item reaches the screen first, and the visible Runtime mounts in the same committed selection update without a second paint wait. This path does not wait for parent Workbench state propagation, focus restoration, disposal work, or Workbench viewport navigation. The desktop sidebar and mobile drawer share `TerminalSessionNavigator`, while terminal text search stays in a surface-local overlay and per-view semantic behavior stays in `TerminalSessionRuntime`; these components consume the panel's existing state and do not establish parallel lifecycle ownership. Switching views never recreates the server-side PTY or VT. A newly mounted or refreshed view opens a generation-bound semantic attachment and receives the current Presentation; transport recovery is finite and visible, while permission, actor, protocol, or semantic validation failures remain fail closed.

Terminal sidebar identity and activity come from the shared execution-context and semantic-work derivation. Local shells use a directory initial and basename; a scheduler-confirmed ordinary local foreground process updates the title and accessibility description without producing an animation; ready remote shells use the Link avatar and validated remote identity without an ongoing spinner; Agent CLIs use audited Agent identity and display name without treating their long-lived process as work. The exact executable basename `pi`, including Windows case and `.exe` normalization, is presented as Pi Agent with its pinned official mark; lookalike names such as `pi-agent` and `pi-cli` remain ordinary processes. `working` uses a three-bar wave, `waiting_user` uses attention, and `idle` is quiet. Process, output, and unread facts remain independent. Output streaming is only an unknown-semantic fallback, unread is lower visual priority, and quiet output never becomes a completion glyph. The closed mobile drawer preserves an active-session status slot and aggregates waiting or unread background attention on the session-menu control; complete truncated title and subtitle text remains available through a keyboard- and touch-operable disclosure. Search covers every visible title, subtitle, identity, and path, including combined SSH and Agent rows. Shortcut index, close, path copy, and Files use an explicit fixed two-by-two rail of 28 px cells on mobile; unavailable actions keep their cells, hidden desktop actions neither intercept the row nor remain hidden on focus, and mobile actions stay visible. Remote paths may be displayed and copied, but Files and duplicate actions stay unavailable because those paths do not identify the local Env filesystem. Local path actions require the separate immutable Redeven creation capability and exact current-path match; execution context remains display metadata. Activity opens the floating file browser and Workbench requests a new Files canvas surface through the existing file-browser handoff.

Terminal session creation, first activation of an unmounted terminal session, and close interactions are UI-first inside the owning panel: sidebar selection or removal reaches the screen before semantic attachment, initial Presentation, delete RPCs, or disposal work begins. Closing a Workbench terminal widget schedules Workbench-scoped cleanup for the sessions currently bound to that widget, but widget removal remains a fire-and-forget UI transition and does not wait for PTY disposal.

# Boundaries

Selected widget boundaries guard canvas zoom. A surface that supports text selection does not automatically own wheel input, and a surface that owns local scrolling must declare the exported wheel contract props. Terminal shortcuts may switch only the current panel's visible sidebar sessions and must preserve platform primary-mod behavior so terminal-native Ctrl sequences are not stolen on macOS. Terminal sidebar path actions are file-browser handoffs only; they must not select the terminal session, bypass read permission checks, create a global file-browser command, or change wheel, text-selection, copy, shortcut, terminal transport, or widget activation ownership. Terminal UI-first scheduling is a responsiveness contract only; it must not pre-mount hidden terminal views, move terminal shortcuts to a global listener, or change terminal transport semantics. A selection transaction superseded before its committed update is cancelled; once committed, the visible target Runtime mounts in that same update without a second paint delay. Rapid A-to-B-to-C selection therefore mounts only the final committed target instead of attaching every briefly previewed row.

Activity and Workbench use the same released semantic renderer, input bridge, and live transport. Redeven must not add a browser VT, raw-output catch-up queue, replay journal, checkpoint, snapshot parser, hidden renderer, or Workbench-only compatibility path. History pages are temporary actor-owned semantic projections bound to the current attachment generation; they never replace or mutate the live Presentation. Only the controller view sends input or canonical resize, and an observer's wheel, crop, selection, search, or theme cannot change the PTY. Initialization or session-selection focus restoration remains generation-bound and is cancelled by search, settings, footer actions, text selections, other controls, or another widget.

On mobile, the session list is a modal Workbench-local drawer over a full-width terminal surface. Opening moves focus to search; Tab and Shift+Tab remain contained; Escape, close, outside click, or browser history restores the session-menu trigger; and selecting any row closes the drawer before any policy-allowed terminal focus restoration. Files and Ask Flower actions launched from the drawer must also close it and release its modal focus ownership before the external surface handoff runs. Env App Workbench surface activation keeps `ensureVisible` and `centerViewport` separate: `ensureVisible` asks the Workbench page to reveal a target only when it is not already projected into the current viewport, while explicit `centerViewport: false` and anchored creation preserve the current viewport. Terminal input focus restoration is separate from Workbench viewport navigation, so focusing an already visible terminal widget must not start a viewport-centering animation or mutate the terminal surface as a visual fallback. Components embedded in projected Workbench surfaces must use the shared floating layer rather than hand-rolling viewport-to-surface coordinates.
