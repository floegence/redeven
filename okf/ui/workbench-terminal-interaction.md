# Summary

Activity and Workbench terminals use Floeterm's single binary `terminal/live_v1` data path over a Flowersec named Yamux stream. Each mounted view owns an independent connection identity and reports its own host capacity, while Floeterm owns the shared PTY geometry, atomic history boundary, ordered output, input, resize acknowledgement, and explicit close/error states. Redeven keeps catalog and history RPCs as a control plane and never falls back to the removed RPC live transport.

# Contract

## Live attachment and multi-view geometry

Every visible terminal view opens `terminal/live_v1`, sends one binary `ATTACH`, and receives an atomic history boundary plus history and geometry generations. Live output begins strictly after that boundary; retained history at or before the boundary is fetched through bounded RPC pages and committed through the paged output coordinator. Missing, malformed, or discontinuous sequence metadata fails closed. Disconnect recovery opens a new named stream and repeats the same attach-and-boundary procedure; it does not switch transports or silently discard output.

Each `TerminalPanel` allocates a fresh connection id, including panels in another browser page or another view in the same page. Views may report different column and row capacities. Floeterm computes the effective PTY grid from all attached connections and broadcasts one geometry generation with an exact output-sequence boundary. Redeven keeps every view's host reporting enabled even while it renders a fixed shared grid, queues geometry events until output through the boundary has reached the parser, and splits a render batch when the boundary falls inside it. Therefore two views apply the same resize between the same output sequences even when their DOM sizes differ. No page claims exclusive attachment ownership and no focus-dependent retry state machine serializes concurrent views.

Attach and resize acknowledgements include the runtime attachment generation, requested local grid, and effective shared grid. Redeven accepts effective facts through one monotonic reducer, rejects stale attachment or renderer epochs, and fails closed on conflicting dimensions within one geometry generation. A structured close invalidates presentation immediately and either removes a closed session or starts reconnect recovery. Hibernation releases only the renderer: it retains the live attachment and ordered geometry candidates, restores a snapshot only when its lifecycle, grid, and output checkpoint match the captured effective fact, and otherwise seeds the new renderer from a confirmed effective fact before replaying history.

When the current visible view has acknowledged a larger local grid but the current renderer has applied a smaller effective grid, Redeven presents a lightweight informational status inside existing Terminal chrome. The status appears only for the active display session in idle recovery state, waits briefly to avoid flicker, and never changes terminal canvas geometry. Its disclosure states that connected views with different available sizes share one grid, shows local and effective dimensions, and explains that the grid adjusts as views resize or disconnect. It does not infer view count, device, window, user, or per-view dimensions. Unselected Workbench widgets render an inert pointer-through visual; selected Workbench and Activity surfaces use a real disclosure button and an explicitly owner-bound surface floating layer. Lifecycle, session, selection, recovery, anchor movement, and confirmed equality close the disclosure without stealing focus, while each live attachment is announced at most once through a polite live region.

Input and resize use the same binary stream. Input bytes are forwarded exactly once and repeated characters remain repeated. Resize promises resolve only after the matching `RESIZE_APPLIED`; a stream end, protocol error, permission denial, missing session, slow consumer, or session close remains an explicit state. `SESSION_CLOSED` removes the session without presenting an ordinary reconnect error. Server error codes are structured Floeterm values rather than parsed message text or legacy RPC status codes.

## Product lifecycle and performance

The Env catalog stays renderer-free and does not statically import the live client, codec, renderer, or Terminal feature chunk. Dormant sessions remain metadata-only. Active-session history warmup may prepare bounded renderer-neutral pages, but it never attaches, resizes, subscribes, starts a PTY, or allocates a Core. A user opening a session row's context menu is an explicit interaction: the owning `TerminalPanel` may promote that exact session into its mounted working set so the [Flower turn launcher](flower-turn-launcher.md) can capture the requested screen without switching the selected session. Ordinary list rendering and background warmup do not promote sessions. Activity and Workbench share catalog state while each mounted runtime owns its Core, live stream, output coordinator, fixed geometry application, focus lifecycle, and working-set snapshot.

Terminal chrome comes from the shared catalog rather than renderer output. Floeterm reports foreground command, output activity, execution context, and semantic work through snapshots and Type IDs 2013 through 2016. One `TerminalPanel` derivation feeds the desktop sidebar, mobile drawer, toolbar, Activity, and Workbench title so responsive placement cannot disagree. A ready remote shell uses its validated `user@authority` or authority label and Link avatar with no ongoing spinner; an opening connection may animate for at most 800 ms. That budget is anchored to the catalog's first observation of one continuous opening epoch, so later context revisions and newly mounted panels cannot restart it. A confirmed ordinary local foreground program becomes the title only after the shared 140 ms presentation scheduler accepts it, while the process-running fact remains available to accessibility descriptions without producing an animation. That process fact remains independent from output and unread attention and is suppressed for remote and Agent CLI contexts, where foreground lifetime alone does not imply Agent work or permanent activity.

For a validated Agent CLI context, Agent identity has title and avatar priority over remote identity, foreground program, and directory fallback. A remote Agent subtitle retains a separate Link marker beside remote identity and path. Revision-fenced semantic `working` shows the three-bar wave and is described as Agent work; `waiting_user` shows restrained, touch-accessible attention; and `idle` shows no status. PTY streaming is an activity fallback only while semantic work is unknown and is described only as terminal output, never as Agent work. Unread attention has lower visual priority but remains an independent fact while work or output is active. A stale work update whose context or foreground-command revision does not match current facts is ignored. Output `settled` remains recent quiet output and never becomes a success or completion glyph. The closed mobile drawer retains a fixed active-session activity slot and places an aggregated background `waiting_user` or unread badge on its session button, with waiting taking priority. A persistent polite live region announces the stable session label and current title with each entry into `waiting_user` or creation/runtime failure, so simultaneous Agent sessions remain distinguishable; output chunks, output revisions, and repeated renders do not reannounce the same boundary, while returning to idle and later re-entering waiting creates a new announcement. Truncated toolbar context opens a focusable, touch-toggle disclosure containing the complete title and subtitle; desktop session rows expose title and path independently, and fixed sidebar width plus row overflow containment prevents long remote identities from covering terminal content. Every `TerminalPanel` owns a unique accessibility-id namespace so session-row and active-toolbar `aria-describedby` references resolve only to status text in the same panel when multiple Terminal widgets are mounted. An open modal mobile drawer owns its portaled row menu through a stable accessibility id, keeps focus within the drawer or that owned layer, and restores focus to the same session row when a waiting, activity, copy, Files, or close control disappears without removing the row. When a kept-alive Terminal view becomes inactive, it closes the mobile drawer and every portaled row or Ask Flower menu without restoring focus into hidden DOM, releasing its document-level Tab, Escape, and focus ownership to the newly active view.

Terminal execution context and current working directory are display metadata, never local filesystem authority. Redeven resolves and grants the product-selected launch directory before a newly created session becomes visible. A trusted `local + ready + shell_integration` Cwd update atomically rotates that grant after the reported path and current session directory agree and the real directory passes scoped filesystem validation. Remote, unknown, untrusted-source, non-ready, malformed, relative, mismatched, deleted, failed/transitioning, or equal-revision-conflicted state revokes it immediately. A list projection may revalidate an existing grant against current session truth, but it cannot mint a grant from display metadata or restore one merely because a deleted path reappears.

Local Files, duplicate session, terminal file links, mobile path/package completion, and filesystem list/read RPCs require that local-path capability. The capability and displayed path independently pass the strict canonical absolute-path validator and must match byte for byte. The validator rejects whitespace aliases, control characters, backslashes, repeated or trailing separators, and `.` or `..` segments instead of normalizing them into authority. Shell-integration Cwd events retain their raw display value through the catalog before this strict comparison; an invalid alias therefore fails closed rather than being rewritten into a capability match. Optimistic pending and failed creation rows may display and copy the requested path but have no local working-directory capability. Remote sessions keep the remote path as subtitle, tooltip, search text, and copy target; Files and duplicate stay visible as focusable disabled actions with a localized explanation that the SSH path is outside the local Environment. Every path action revalidates current location and product capability at admission so a context change cannot reuse stale authority.

Terminal file-link hover is a lexical presentation step and performs no filesystem lookup or RPC. The provider reads exactly the zero-based buffer row requested by Floeterm and returns ranges on that same row; it never falls back to an adjacent line, because doing so would move the hover target and underline away from the source text. Absolute, home-relative, dot-relative, and parent-relative candidates may name extensionless files. Other relative candidates require a directory separator and a basename with an extension, a recognized extensionless filename, or hidden-file form. Only matching paired outer quotes or brackets are removed; remaining code, regex, shell, glob, HTML, URL, or nonnumeric line/column delimiters reject the whole token. A valid hover underlines only the candidate cells. Ordinary click remains terminal input, while Cmd/Ctrl click admits the resolved target through the existing local-path capability before opening preview.

Ask Flower is a terminal-snapshot action rather than a local-path action. It remains available for every visible terminal row and surface, including pending creation, creation failure, unknown context, SSH opening, SSH ready, and a revoked local capability. It captures an explicit selection or the latest bounded screen text when available. A verified local capability may add `working_dir` and `suggested_working_dir`; otherwise both fields are omitted, never empty and never inferred from remote or unverified display paths. An empty snapshot still opens the launcher with an explicit localized note instead of disabling the action. The persistent session name is not rewritten. Creation failure and blocking runtime failure share the visual failure priority but expose distinct localized accessible descriptions.

Terminal input-plane behavior remains upstream-owned. Redeven consumes released Floeterm APIs and verifies native focus, IME, canvas geometry, retained history, ordered shell integration, clear/delete behavior, and multi-view resize without compatibility branches. Mobile keyboard retention does not imply textarea autofocus. Surface disposal invalidates asynchronous reload and writer work so an unmounted surface cannot reopen a stream later.

Fixed-performance validation remains separate from ordinary hosted timing. Deterministic tests enforce sequence continuity, parser ordering, no fallback, bundle boundaries, and no silent drop. Controlled-runner reports cover key-to-paint, high-volume output, render frames, UI responsiveness, reconnect leakage, and same-session multi-view resize/content convergence. Activity and Workbench may have different host sizes, but both must converge on the protocol geometry generation and output boundary rather than accepting coarse content divergence as normal.

## Focus recovery

The desktop sidebar applies the same session-scoped recovery as the mobile drawer when a waiting, activity, copy, Files, or close control disappears, restoring focus to the same row; when the row itself disappears, both placements choose the adjacent row or stable filter fallback. A rebuilt open row menu preserves the focused action by stable id and moves focus to the next available action if a capability change disables it.

# Boundaries

Redeven may map Flowersec `openStream("terminal/live_v1")` into Floeterm's byte-stream adapter and may provide RPC catalog/history operations. It must not recreate Floeterm framing, attachment arbitration, effective-grid calculation, input sequencing, resize acknowledgement, output batching, slow-consumer policy, context inference, semantic-work parsing, or error-code semantics. RPC type ids 2003 through 2006 are intentionally unregistered and have no SDK codec, debug projection, queue, or fallback path. Control notifications such as session-list, name/working-directory, foreground-command, output-activity, execution-context, and work-state changes remain RPC control-plane events and are synchronously offered only to clients whose access-gate channel is currently unlocked and whose immutable session permissions still allow process launch. The global catalog accepts only complete, validated payloads, retains bounded early truth, and delegates equal-revision payloads to Floeterm's conflict detector. Conflicting execution context becomes unknown immediately so it cannot retain local-path authority, records only a content-free diagnostic, and schedules one bounded reconcile whose authoritative list value wins the equal revision. Overflow also reconciles authoritatively.

Hydration does not weaken this conflict boundary. If two early context notifications for one session carry the same revision with different payloads before the first catalog list completes, the retained context becomes `unknown` at that revision. The initial list cannot restore path authority while the conflict reconcile is pending; only the subsequent authoritative list may replace the unknown projection at an equal revision. Conflict masks are generation-bound: a completed list clears only masks that existed before its final request began, so a newer conflict remains fail closed through the next delayed or failed reconcile.
