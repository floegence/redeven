# Summary

Redeven projects canonical Floret summaries and matching current-run detail into one compact Flower status. Active work, pending actions, and user-owned drafts retain explicit precedence; historical completion never masquerades as new feedback. Presence shares the existing workspace stream and does not auto-expand, claim transcript reads, or recreate thread lifecycle state. A disconnect follows the existing transport refresh contract. [Flower Activity companion](flower-activity-companion.md) owns placement, native composer identity, dismissal, and read acknowledgement.

# Contract

## Status and live output

Bottom Bar presence is a pure canonical summary projection with active work first: running, queued, attention, unread failure, unread canceled, unread completed, unavailable, idle. A selected pending approval or secret-input action has higher visual priority than that projection because it is an actionable composer kind, not a historical presence count. The per-thread classifier uses the same active-first order, so a running or queued turn is not swallowed by an older waiting or terminal status on that thread. Counts for every canonical group remain available to the expanded Flower UI; running, queued, and canonical unread failure qualify for collapsed Bottom Bar presentation. A displayed title consumes the non-empty canonical title in ready, pending, or failed automatic-title state because Floret retains the first-message fallback until provider success. Empty or missing titles and inferred preview text are not usable. Companion presence still covers the complete summary collection, including titleless threads filtered out of the sidebar list, and every displayable status carries its exact target thread identity.

The collapsed visual line describes current work instead of exposing aggregate counters. Running shows its live progress, queued shows an explicit waiting-to-start summary, and an unread failed thread shows a localized task failure until the exact thread has genuinely been displayed and canonical read state clears it. While current detail remains cached, a documented safe error code may contribute its localized reason; unknown or reload-only failure detail falls back to the canonical title or generic localized Flower failure copy and never exposes an arbitrary provider message. Attention without a selected actionable composer, cancellation, and historical completion do not produce a collapsed summary, colored marker, tooltip, accessible name, or live announcement. Bare aggregate output such as `Failed · 1`, `Needs review`, or `One task needs your attention` remains forbidden. The expanded companion and dedicated Flower page remain the complete surfaces for inspecting and acting on all thread states.

Running work is a live tail of the priority thread's current exact RunID, never its user input, an earlier run, or inferred thread-title text. Canonical `preparing`, `waiting_response`, `streaming`, `retrying`, `finalizing`, and `tool_execution` phases produce the localized status. Raw thinking content is not exposed. The phase always comes from Floret; a current-turn tool or assistant block may contribute only the collapsed presentation text. Block order decides which visible content is current.

The running visual line contains only that status, tool summary, or output; the thread title and aggregate count do not compete for its single row. Assistant output uses a clipped normal-flow viewport. Only overflow enables the leading fade and ellipsis. Stable thread, exact active run, message, and block identity plus reliable rolling-window overlap reconstruct genuine appends locally, and one animation-frame follower advances smoothly toward the newest edge as tokens arrive. Identity changes, rewrites, current-view replacement, expansion, hidden state, reduced motion, or a large burst snap directly to the newest text. The reconstruction buffer has a hard bound and compensates scroll when trimming content already offscreen. Tool summaries preserve their action-leading text and use ordinary end ellipsis, as do status and queued summaries. The button tooltip and accessible name expose the complete current text and add any remaining running count. Phase, completion, and failure changes use a restrained polite atomic announcement, while high-frequency tool and output changes do not trigger repeated live announcements. Running uses a low-frequency status pulse and one-pixel flowing highlight. Completion settles once into a green wash, while failure flashes a red edge once and then stays static. Reduced motion disables flow, transition tracking, and arrival motion while retaining semantic color and text.

## Completion acknowledgement

A successful transition for a run that the collapsed companion previously observed as running may temporarily replace the idle composer with one localized completion acknowledgement. This is ephemeral product feedback, not canonical completed presence: initial history, queued-only work, failures, cancellations, attention, mismatched or expired runs, and completion while any running or queued work remains never trigger it. A process-local observer binds only accepted `thread.batch current` exact RunIDs to a local generation and emits a receipt only for that same RunID's later accepted terminal view. The identity-bound completion controller tolerates the short gap between live terminal state and canonical summary, shows the acknowledgement for about four seconds without refresh extending it, and prevents an older timer from clearing a newer acknowledgement. New work, access loss, opening the companion, entering the dedicated Flower page, or disposal clears it immediately. The completion state uses a success point, soft wash, and one restrained settle motion; reduced motion keeps the same static semantic state. It sends one polite atomic announcement and selects its exact thread before opening Flower detail. Historical completion remains forbidden from the collapsed Bottom Bar.

## Observation and transport

The companion consumes the same single workspace SSE as the full Flower surface. Complete summary batches remain the authority for lifecycle counts and unread state. Matching cached typed current detail contributes only the active run's visible output, tool presentation, and documented safe localized failure reason; it never mutates or replaces the summary projection. Accepted typed current updates also feed the process-local terminal observer without adding a selection-specific connection. `LiveTransport` fences stale callbacks with its process-local connection epoch and reconnects with bounded backoff. After disconnect it refreshes summaries and the selected current view; it does not poll, replay cursors, or run a second companion transport.

The visible presence owner performs one initial summary bootstrap and then relies on SSE `summary.batch` envelopes. There is no 1.8-second inventory timer, fixed live-event polling loop, or background full-history refresh. Heartbeats keep a healthy connection alive without application requests; inactivity aborts the reader after 45 seconds and lets the bounded reconnect policy recover. Hidden or disposed documents clear the reader and renderer work, so idle observation does not create a CPU or network loop. Expansion keeps the same connection and requests the selected thread current view rather than creating a second stream.

## Composer precedence

The collapsed companion has three mutually exclusive content classes, in priority order: a pending approval or secret-input action; a running, queued, unread-failure, or eligible ephemeral-completion status button; or the ordinary textarea. The left thread-switcher entry exclusively owns the Flower glyph. A status button contains only its semantic marker and single-line summary, selects its exact target thread, and only then opens the companion detail surface. It appears only when the textarea draft is empty after trimming, focus is elsewhere, and IME composition is inactive. A pending action owns both visible and accessible status through its explicit action button; the companion summary live region is absent while that button is shown. While a status or pending action is visible, the ordinary textarea remains mounted for identity continuity but its content container is hidden, `inert`, and removed from accessibility navigation. There is no draft recovery, conflict, takeover, or store-unavailable presentation. A connection-local draft, caret, selection, or composition session otherwise always wins.

# Boundaries

Presence is a read-only projection of canonical work and local composer intent. It never admits work, changes lifecycle state, or acknowledges transcript reads. Placement and focus remain owned by the Activity companion contract; transport recovery remains owned by the shared Flower runtime boundary.
